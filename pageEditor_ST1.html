Template & Navigation

View Home Page  |  View validation evidence

HTML Structure

Every page shares a single structural skeleton: a <header> containing the logo and a <nav> with the site's main links, a <main> region that each page fills with its own content, and a shared <footer> with links to the relevant Page Editor and Validation Report. Using the same semantic landmarks on every page means the site structure is predictable for both users and assistive technology, and it's the reason all pages validate against the same baseline markup.

CSS Techniques

The navigation bar uses Flexbox (display: flex) to align the logo and links, with justify-content: space-between so the layout adapts automatically as links are added or the viewport narrows. The pill-shaped navbar uses a large border-radius and a soft box-shadow to look like it's floating above the page, and I later made it translucent using background: rgba(255,255,255,0.65) combined with backdrop-filter: blur(14px) so it reads clearly on top of any background image without hiding it completely.

Design and Implementation Rationale

I kept all shared visual colours, fonts, the navbar, card styles, and the footer in the global stylesheet so that every teammate's page automatically looks consistent without needing to duplicate CSS. Page-specific styling is kept in each page's own embedded <style> block instead, so it can't accidentally override shared rules that other pages depend on.

Home Page

View live page  |  View validation evidence

HTML Structure

The Home Page contains the shared <header> inside a .hero-wrap container so the background photo runs edge-to-edge behind the navbar. Below that, <main> contains an <article>-style grid of three content cards (using semantic <article> elements, each with its own heading, image and list), followed by a second grid of four <a>-based tiles linking to each team member's Content Page.

CSS Techniques

The card grid and topic-tile grid both use CSS Grid with repeat(auto-fit, minmax(...)), which lets the number of columns adapt automatically to the screen width without needing separate media-query breakpoints for every card count. The topic tiles use a transform: scale() on the image and a gradient overlay that slides into view on hover, giving clear visual feedback that they're clickable.

Design and Implementation Rationale

The three content cards were designed around the spec's requirement to explain why the SDG matters, who it's relevant to, and what action looks like rather than just describing the goal itself. The topic-tile gallery exists specifically to connect visitors from the Home Page into each teammate's individual Content Page.

Gallery Page

View live page  |  View validation evidence

HTML Structure

Each gallery thumbnail is a focusable <div> with tabindex="0" and data-* attributes holding its title, description and image path, so the extended-view content can be read directly from the markup by JavaScript rather than being hard-coded per item. The extended view itself is a single reusable modal, not a separate element per photo.

CSS Techniques

Hover and focus states are styled through a .js-hover class rather than the :hover pseudo-class, because the spec requires the interaction logic itself to be handled in JavaScript, not CSS alone. The modal uses position: fixed and inset: 0 to overlay the full viewport, and two toggle classes (.theme-dark, .font-serif) let the colour scheme and font of the extended view change without touching the rest of the page.

Design and Implementation Rationale

I used JavaScript addEventListener calls for hover, click, and keyboard (Enter/Space) interaction so the gallery is usable without a mouse, and added Escape-to-close and click-outside-to-close behaviour so the modal never traps a user without an obvious way out.

Content Page - Solar Power for Homes

View live page  |  View validation evidence

HTML Structure

The page uses one <h1> for the page title, then six <section> elements each with a unique id and its own <h2>, with <h3> subheadings inside the "How It Works" section to show a genuine heading hierarchy rather than everything sitting at the same level.

CSS Techniques

A "jump to section" menu near the top uses anchor links (href="#section-id") styled as rounded chips, giving quick internal navigation as required for pages long enough to need it. The "Go to Top" control is a plain <a href="#page-top"> styled with position: fixed deliberately built with HTML and CSS only, with no JavaScript, per the coursework specification.

Design and Implementation Rationale

Content was written from scratch around realistic, achievable actions (getting quotes, checking community solar schemes, using the Impact Simulator) rather than summarising the SDG itself, to meet the brief's requirement for original, action-focused content rather than a description of the goal.

Challenges & Lessons Learned

Challenge 1:

Inconsistent Nav Bar Hover Effect Across Pages while testing the site, I noticed that hovering over a nav link on the Home page produced a clear, visible highlight, but the same hover effect looked much fainter on the Gallery page.

Solution: Instead of relying on the background behind the navbar for contrast, I changed the hover style to use a semi-transparent tint of the primary blue colour (rgba(18, 62, 115, 0.1)) instead of the light background colour.

Lesson Learned: Effects like backdrop-filter only work well when there's contrast between the element and what's behind it

Challenge 2:

Images not loading after testing on a different environment because windows treats file names as case-insensitive, so home_card1.jpeg and Home_Card1.jpeg are treated as the same file. Most web servers and browsers checking against them are case-sensitive.

Solution: Standardise a naming convention across the whole project.

Lesson Learned: A site can work perfectly during local development and still break the moment it's deployed or shared.

Accessibility Considerations

Across the pages I built, I applied the following accessibility practices:

  • Semantic HTML landmarks (<header>, <nav>, <main>, <section>, <footer>) so screen readers can navigate the page structure directly.
  • Meaningful, distinct alt text on every image, describing what the image shows rather than repeating the surrounding heading.
  • Keyboard accessibility on the Gallery Page: every thumbnail has tabindex="0" and responds to Enter/Space, and the modal can be closed with the Escape key.
  • Visible focus states (:focus-visible) on interactive elements, so keyboard users can always see where they are on the page.
  • Sufficient colour contrast between text and background, checked manually against the site's blue/white colour palette.

These choices matter because they mean the site remains usable for people relying on screen readers, keyboard navigation, or who simply have a slower or less precise pointing device.
